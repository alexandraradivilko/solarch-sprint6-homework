# Доменные data-продукты

| Data product | Домен / связь с BIAN | Основные данные | Владелец | Потребители |
|---|---|---|---|---|
| Customer Identity | Клиентский домен / Party Reference Data Directory | Общий ID, подтверждённые соответствия, тип лица, сегмент, разрешённые контакты и ограничения использования | Бизнес-владелец клиентских данных группы | CRM, DWH, риск-менеджмент |
| Account Position | Счётный домен / Current Account и профильные области других счетов | Счёт, банк, валюта, вид остатка, сумма и момент среза; связь с клиентом | Владелец счётного продукта соответствующей бизнес-линии | Финансовый департамент, BI, риск-менеджмент |
| Payment Analytics | Платёжный домен / Payment Order, Payment Execution | Исполненные платежи и измерения звезды; суммы и количество по валюте, периоду, продукту, каналу | Владелец платёжного сервиса; финансовый департамент утверждает отчётные метрики | BI, финансовый департамент, продуктовые аналитики |

Границы BIAN продолжают [Task1](../Task1/reference-model.md), роли владельцев соответствуют [Task2](../Task2/data-ownership.md). Customer Identity публикуется из MDM, остальные продукты из проверенных витрин DWH.

Элементы Data Mesh: доменный владелец отвечает за контракт и качество своего набора; общая платформа предоставляет хранение, загрузки и доступ. В DataHub для каждого продукта фиксируются зерно, ключи, схема/версия, владелец, потребители, свежесть, проверки и права. Data Office согласует общие определения и правила. Разделение физической инфраструктуры по доменам не требуется.
