# Управление потоками

SLA ниже являются проектными целями: задержка измеряется от фиксации изменения у указанного источника до подтверждения приёмником. Для batch указаны срок готовности или время после закрытия пакета; для F09 время ответа на запрос. При нарушении SLA оповещается владелец потока.

| ID | Источник | Приёмник | Сущность | Действие | Формат | Частота | Тип обмена | SLA | Владелец потока | Контроль качества | Безопасность | Мониторинг |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| F01 | FU/RB CRM | Integration Layer | Клиент, обращение, согласие, метаданные документа | Read/Validate | JSON | При изменении | Async | ≤ 1 мин | Руководитель CRM-интеграций | Схема, исходный ID, обязательные поля | TLS, сервисные роли, минимум ПДн | Задержка, ошибки схемы, очередь недоставленных |
| F02 | FU/RB Core | Integration Layer | Счёт, договор, платёж, операция, остаток, реквизиты и каталоги | Read/Validate | JSON; Parquet-срез | CDC постоянно; срез ежедневно | CDC + batch | Изменения ≤ 5 мин; срез D до 06:00 D+1 МСК | Руководитель интеграций Core | Позиция журнала, количества и суммы по банку/дате/валюте | TLS, чтение журналов отдельной ролью, шифрование файлов | CDC lag, разрыв позиций, готовность среза |
| F03 | FU/RB Cards | Integration Layer | Карта, договор, каталоги, ID держателя | Read/Validate | JSON | При изменении | Async | ≤ 5 мин | Руководитель карточных интеграций | Токен, счёт, статусы, уникальность события | TLS, токены вместо PAN | Задержка, повторы, неподдержанные статусы |
| F04 | FU/RB Loans | Integration Layer | Кредит, договор, график, каталоги, ID клиента | Read/Validate | JSON | Непрерывно | CDC | ≤ 5 мин | Руководитель кредитных интеграций | Договор, валюта, версия графика, ссылки | TLS, сервисные роли | CDC lag, ошибки ссылок, пропуски версий |
| F05 | Integration Layer | MDM | Клиент/ID, ограничения, каталоги | Validate/Enrich/Create/Update | JSON | При поступлении | Async | Автообработка ≤ 2 мин; спорные связи: разбор ≤ 1 раб. дня | Руководитель MDM | Правила сопоставления, тип лица, источник атрибута, интервалы кодов | TLS, право изменения эталона только MDM/steward | Доли дублей, конфликтов, возраст очереди разбора |
| F06 | MDM | Integration Layer | Эталоны и версии соответствий | Read/Enrich | JSON | После утверждения | Async | ≤ 1 мин | Руководитель MDM | Версия эталона, существование ссылок | TLS, разрешённые поля, аудит публикации | Отставание публикации, версия кэша, подтверждения |
| F07 | Integration Layer | FU/RB CRM | Профиль и справочные проекции | Update/Delete | JSON | После F06 | Async | ≤ 1 мин | Руководитель CRM-интеграций | Совпадение локального ID, версия, отсутствие обратного цикла | TLS, ограничение полей, аудит удаления | Подтверждение каждой CRM, повторные доставки |
| F08 | Integration Layer | DWH | Сущности F01–F04, эталоны F06 | Create/Update/Delete/Validate/Enrich/Aggregate | Parquet + манифест | Каждые 15 мин; суточная сверка | Batch | ≤ 30 мин после готовности входов; срез D до 08:00 D+1 МСК | Руководитель DWH | Полнота источников, ссылки, контрольные суммы, остатки | Шифрование, роли загрузки, маскирование ПДн | Свежесть, длительность, карантин, результат сверки |
| F09 | DWH | BI | Опубликованные витрины | Read | SQL / табличный результат | По запросу | Sync | Типовой запрос ≤ 10 сек | Руководитель BI | Принятая версия среза, общие определения метрик | Read-only, права на строки/поля | Время ответа, ошибки, версия витрины |
| F10 | DWH | Регуляторная отчётность | Утверждённый отчётный срез | Read/Aggregate | Формат конкретной формы, например XML | По календарю форм | Batch | К внутреннему сроку: минимум за 1 час до срока подачи | Финансовый департамент | Финансовая сверка, схема формы, утверждение ответственного | Защищённый канал, подпись по требованиям формы | Готовность, отправка и подтверждение приёма |
| F11 | Integration Layer/MDM/DWH/BI | DataHub | Метаданные, lineage, DQ | Create/Update | JSON metadata events | После изменения схемы/запуска загрузки | Async | ≤ 15 мин | Data Office | Владелец, классификация, исходные/целевые наборы, ID запуска | Сервисные роли; без значений ПДн | Ошибки публикации, полнота lineage, давность метаданных |

Для F01 → F05 → F06 → F07 дополнительно контролируется сквозная задержка автоматического обновления профиля: ≤ 5 минут. Для F08 отдельно контролируется возраст исходного события: ожидание зависимостей не скрывается за временем самой загрузки. Локальные каталоги на F02–F04 передаются при изменении; новые условия публикуются только после утверждения владельцем.

Повтор доставки обрабатывается идемпотентно по `(source_system, entity_id, event_version)`; порядок контролируется внутри объекта. Ошибочные сообщения сохраняются в карантине с причиной, повтор запускается после исправления. При финансовом расхождении публикация затронутого среза блокируется; BI использует последний принятый срез с отметкой времени. Все потоки сохраняют исходный ключ, ID события/пакета и версию преобразования.
