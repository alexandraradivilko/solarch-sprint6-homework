# Мастер-системы

Источник As-Is показывает место хранения, первичное создание показывает место возникновения записи, мастер определяет эталон и публикацию изменений. В паре FU/RB мастер выбирается по банку и объекту: совместной записи одного объекта в два мастера нет.

| Сущность | Источники As-Is | Где впервые создаётся | Мастер на 3 месяца | Целевой мастер, 12 месяцев | BIAN / граница | Обоснование |
|---|---|---|---|---|---|---|
| Клиент | FU/RB CRM, Core; копии Cards/Loans | CRM при регистрации; Core при банковской идентификации | MDM Customer Hub: общий ID и золотая запись | MDM Customer Hub | Party Reference Data Directory | Объединение идентичности при сохранении происхождения атрибутов |
| Соответствие клиентских ID | Локальные ID в CRM/Core/Cards/Loans; общего реестра нет | Новый процесс сопоставления MDM | MDM Customer Hub | MDM Customer Hub | Внутри клиентского домена | Единая подтверждённая связь локального и общего ID |
| Договор | FU/RB Core, Cards, Loans | Система оформления соответствующего продукта | Core для счетов, Cards для карт, Loans для кредитов своего банка | Соответствующие FU Core / FU Cards / FU Loans | Sales Product Agreement | Эталон условий находится в системе обслуживания договора |
| Счёт | FU/RB Core; копии DWH | Core при открытии | Core банка, ведущего счёт | FU Core с разделением учёта по юридическим лицам | Current Account; профильные области для других счетов | Остаток и статус управляются операционным учётом |
| Карта | FU/RB Cards; ссылки Core/CRM | Cards при выпуске | Cards банка-эмитента | FU Cards | Issued Device Administration: выпуск и назначение | Карточный контур управляет инструментом; счётом управляет Core |
| Кредит | FU/RB Loans, Core | Loans при оформлении | Loans своего банка: условия/график; Core: учётная задолженность | FU Loans: условия/график; FU Core: учёт | Consumer Loan / Corporate Loan | Разделение продуктовых и бухгалтерских атрибутов |
| Операция | FU/RB Core, Cards/Loans; копии DWH | Продуктовое событие в Cards/Loans либо операция в Core | Core своего банка для проведённого факта и проводок | FU Core | Position Keeping | Сообщение процессинга не подменяет учётный факт |
| Платёж | FU/RB Core; каналы и партнёрские сообщения | Канал создаёт запрос; платёжный модуль Core регистрирует распоряжение | Платёжный модуль Core своего банка | Платёжный модуль FU Core | Payment Order / Payment Execution | Эталон распоряжения и исполнения находится в платёжном контуре |
| Продукт | Настройки FU/RB Core, Cards, Loans; каталоги CRM | Продуктовая команда в профильной системе | MDM: единый каталог и маппинг; локальные конфигурации остаются в профильных системах | MDM: утверждённый каталог; профильная система: исполнение | Product Directory | Канонический продукт отделён от локальной реализации |
| Тариф | FU/RB Core, Cards, Loans; копии CRM | Продуктовая команда утверждает условия в профильной системе | MDM: версии и соответствия; условия действующих договоров в их системах | MDM: стандартные тарифы; индивидуальные условия в системе договора | Каталог продукта / Sales Product Agreement | Обновление каталога не переписывает договорные условия |
| Обращение | Предположительно FU/RB CRM | CRM через контактный центр/канал | CRM, зарегистрировавшая обращение | FU CRM | Customer Case для претензий | Один ответственный контур жизненного цикла обращения |
| Справочное значение | FU/RB CRM, Core, Cards, Loans, DWH | Владелец справочника в исходной системе | MDM: канонические значения и маппинг кодов | MDM | Location Data Management для отделений; прочие по предметной области | Согласованные коды и версии для обмена и отчётов |
| Документ | Вложения приложений и файловые ресурсы; точный состав уточняется | Приложение оформления/приёма документа | Реестр и файл исходного приложения | Единый реестр документов + объектное хранилище | Сквозные документы доменов Task1 | Эталон включает версию метаданных и проверяемое содержимое |
| Согласие | Предположительно FU/RB CRM и каналы | Канал получает согласие/отзыв; CRM регистрирует доказательство | CRM своего банка по цели и области действия | Реестр согласий в FU CRM | Ограничения использования клиентских данных | MDM получает проекцию ограничений, но не создаёт согласие |

**Выбор значения клиента:** подтверждённые идентификационные реквизиты поступают из Core, верифицированные контакты из CRM. При конфликте подтверждённых значений решение принимает steward; одна лишь свежесть записи не разрешает конфликт. MDM хранит источник каждого выбранного атрибута.

Мастером для `AgreementParty` является система договора, для `Posting` Core, для `DocumentLink` реестр документов. DWH и BI являются потребителями. Границы BIAN взяты из [маппинга Task1](../Task1/reference-model.md); отдельный платёжный модуль Core принят как допущение до обследования.
